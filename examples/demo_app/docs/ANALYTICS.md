# Analytics

Generated by [flutter-analytics-autopilot](../../../skills/flutter-analytics-autopilot).
Regenerate the event table with `node <skill>/scripts/catalog.mjs --root .`.

## How it is wired

Call sites use one API, `Analytics` (`lib/core/analytics/analytics.dart`). It forwards to
`AnalyticsService`, which merges the base attributes into every event and fans out to
Firebase Analytics and AppMetrica. Nothing else talks to an SDK, so there is exactly one
place where an event can be dropped, renamed or deduplicated.

Screens are reported by two navigator observers registered on the router. Both read
`route.settings.name`, which is why every route, bottom sheet and dialog is named.

`main.dart` starts analytics **after** the first frame: `runZonedGuarded` catches uncaught
errors into `app_error`, then a deferred block activates AppMetrica, seeds the base
attributes, syncs the anonymous profile and fires `app_opened`.

Firebase is guarded by `kFirebaseConfigured`. Until someone runs `flutterfire configure`,
events go to AppMetrica only and nothing crashes. Build with
`--dart-define=FIREBASE_CONFIGURED=true` once the config files exist.

Funnels (`analytics/funnels.json`): **browse** `app_opened → home_details_opened →
details_shared`; **sign_out** `settings_sign_out_tapped → settings_sign_out_completed →
session_signed_out`.

## User properties

`plan`, `locale`, `notifications_enabled`, `platform`, `app_version`, plus the predefined
AppMetrica attributes (gender, birth date, notifications). Set through `UserProfileSync`:
`syncAnonymous` at bootstrap, `sync` on sign-in and plan change, `clear` on sign-out.

The display name is deliberately **not** a property: `settings_display_name_submitted`
carries only its length. The same rule applies to anything a user types.

## Not tracked, on purpose

* `onChanged` of the display-name field — per-keystroke events are noise and a PII risk.
* The two buttons inside the sign-out dialog — the outcome is reported once, with
  `confirmed: true|false`, where the result is awaited.

## Verifying

```bash
flutter test                                   # instrumentation smoke tests
node <skill>/scripts/coverage.mjs --root .     # must print COVERAGE COMPLETE
```

In a debug run every event prints one `Analytics: …` line. For the real consoles see the
skill's `references/verification.md` (Firebase DebugView, AppMetrica Live stream).

Before reporting on them in GA4, register the event parameters and user properties above as
custom definitions — unregistered ones are invisible to the GA4 Data API.
